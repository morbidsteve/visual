# Network Visualizer for SOC

A real-time network topology visualization tool designed for Security Operations Centers (SOC). This application pulls netflow data from Elasticsearch (generated by Zeek from network taps) and provides an interactive, visual representation of your network infrastructure.

## Features

- **Real-time Network Visualization**: Interactive graph visualization using Cytoscape.js showing hosts, servers, routers, and network connections
- **Elasticsearch Integration**: Pulls Zeek netflow data directly from Elasticsearch
- **Intelligent Node Classification**: Automatically identifies and classifies network entities (servers, routers, DNS servers, web servers, etc.)
- **Advanced Filtering**:
  - Time range filtering (1 hour to 7 days)
  - IP-based filtering (source, destination, subnet)
  - Traffic volume filtering
  - Protocol and service filtering
- **Whitelist Management**: Filter out known-good traffic to focus on anomalies
- **Interactive Graph Controls**:
  - Pan, zoom, and drag nodes
  - Click nodes/connections for detailed information
  - Automatic layout with subnet grouping
- **Search Functionality**: Quick search across IPs, services, and protocols
- **Responsive UI**: Clean Material-UI interface optimized for SOC operations
- **Kubernetes-ready**: Full deployment manifests for production environments

## API Documentation

### Network Endpoints

#### GET `/api/network/topology`
Get network topology data with optional filters.

**Query Parameters:**
- `timeRange` - Hours to look back (1-168)
- `sourceIp` - Filter by source IP
- `destIp` - Filter by destination IP
- `subnet` - Filter by subnet prefix
- `minBytes` - Minimum traffic volume
- `hideWhitelisted` - Hide whitelisted entries (true/false)

**Response:**
```json
{
  "nodes": [...],
  "edges": [...],
  "stats": {
    "uniqueSources": 150,
    "uniqueDestinations": 300,
    "protocols": [...],
    "services": [...]
  }
}
```

#### GET `/api/network/connection/:sourceIp/:destIp`
Get detailed connection information between two IPs.

#### GET `/api/network/search?q=<query>`
Search network data for IPs, services, or protocols.

### Whitelist Endpoints

#### GET `/api/whitelist`
Get all whitelist entries.

#### POST `/api/whitelist`
Add entry to whitelist.

**Body:**
```json
{
  "entryType": "ip|subnet|connection|protocol",
  "value": "192.168.1.100",
  "description": "Corporate web server"
}
```

#### DELETE `/api/whitelist/:id`
Remove entry from whitelist.

## Zeek Data Requirements

This application expects Zeek connection logs in Elasticsearch with the following fields:

- `@timestamp` - Event timestamp
- `id.orig_h` - Source IP
- `id.orig_p` - Source port
- `id.resp_h` - Destination IP
- `id.resp_p` - Destination port
- `proto` - Protocol (tcp, udp, icmp)
- `service` - Identified service (http, dns, ssh, etc.)
- `orig_bytes` - Bytes from originator
- `resp_bytes` - Bytes from responder
- `orig_pkts` - Packets from originator
- `resp_pkts` - Packets from responder
- `conn_state` - Connection state

## Usage Guide

### Viewing Network Topology

1. The main view shows your network as an interactive graph
2. **Nodes** represent hosts, servers, routers, etc. (colored by type)
3. **Edges** represent network connections (colored by protocol)
4. Node size indicates connection volume
5. Edge thickness indicates traffic volume

### Filtering Data

Use the left sidebar to apply filters:
- **Time Range**: Adjust the time window (1 hour to 7 days)
- **IP Filters**: Filter by specific source/destination IPs or subnets
- **Traffic Volume**: Show only high-volume connections
- **Hide Whitelisted**: Toggle to hide known-good traffic

### Investigating Connections

1. Click on a **node** to see host details (traffic stats, connections)
2. Click on an **edge** to see connection details (protocols, services, states)
3. Use the **search bar** to quickly find specific IPs or services

### Managing Whitelist

1. Click the whitelist icon in the top-right
2. Add entries for known-good traffic:
   - **IP**: Whitelist specific hosts
   - **Subnet**: Whitelist entire subnets
   - **Connection**: Whitelist specific source->destination connections
   - **Protocol**: Whitelist protocols
3. Toggle "Hide whitelisted traffic" to apply filters

### Graph Controls

- **Click & Drag**: Pan around the graph
- **Scroll**: Zoom in/out
- **Drag Node**: Reposition individual nodes
- **Click Node/Edge**: Select and view details
- **Click Background**: Deselect all

## Security Considerations

1. **Elasticsearch Credentials**: Store securely in Kubernetes secrets or environment variables
2. **TLS/SSL**: Enable TLS in production (configure ingress with cert-manager)
3. **Authentication**: Consider adding authentication layer (OAuth, LDAP, etc.)
4. **Network Policies**: Use Kubernetes network policies to restrict traffic
5. **RBAC**: Configure Kubernetes RBAC for deployment management
6. **Data Sensitivity**: Network topology data may be sensitive - secure appropriately

## Troubleshooting

### Backend won't connect to Elasticsearch

- Verify `ES_NODE`, `ES_USERNAME`, and `ES_PASSWORD` are correct
- Check Elasticsearch is reachable from the backend container
- Verify the Zeek index pattern matches your data (`ES_INDEX_PATTERN`)
- Check backend logs: `docker logs network-visualizer-backend`

### No data showing in graph

- Verify Zeek data exists in Elasticsearch for the selected time range
- Check the index pattern and field mappings
- Verify Elasticsearch query permissions
- Try adjusting time range filter to a wider window

### Frontend can't reach backend

- Verify backend is running and healthy
- Check nginx configuration in frontend container
- Ensure services are properly configured in Kubernetes
- Check ingress configuration

### Performance issues

- Increase backend replicas in Kubernetes
- Adjust HPA settings for auto-scaling
- Reduce time window for queries
- Increase minimum bytes filter to reduce node count
- Consider adding Redis caching layer
